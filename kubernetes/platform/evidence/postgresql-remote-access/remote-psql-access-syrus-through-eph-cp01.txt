1. Start the SSH Tunnel and Kubernetes Port Forward
---------------------------------------------------

Option A — Foreground Tunnel
----------------------------

Use this when you want to keep the SSH tunnel visible in the terminal:

ssh -i /home/alabi/.ssh/eph_k8s \
  -L 15432:127.0.0.1:15432 \
  mino@172.16.10.31 \
  'kubectl port-forward -n havenbridge pod/havenbridge-postgres-0 15432:5432 --address 127.0.0.1'


Option B — Background Tunnel
----------------------------

Use this when you want SSH to move into the background after the tunnel is
established:

ssh -f \
  -i /home/alabi/.ssh/eph_k8s \
  -L 15432:127.0.0.1:15432 \
  -o ExitOnForwardFailure=yes \
  mino@172.16.10.31 \
  'kubectl port-forward -n havenbridge pod/havenbridge-postgres-0 15432:5432 --address 127.0.0.1'

What this command does:
- SSH connects from syrus to eph-cp01.
- The local port 15432 on syrus is forwarded through SSH.
- kubectl port-forward on eph-cp01 forwards port 15432 to PostgreSQL port
  5432 inside havenbridge-postgres-0.
- PostgreSQL remains unexposed to the LAN because access is carried through
  the SSH tunnel.

2. Validate PostgreSQL Access from syrus
----------------------------------------
Run:

psql -h 127.0.0.1 -p 15432 \
  -U havenbridge_admin \
  -d havenbridge

Flag explanation:
- -h 127.0.0.1
  Connect to the local loopback interface on syrus. The SSH tunnel is
  listening here.

- -p 15432
  Connect to local TCP port 15432 rather than PostgreSQL's normal port 5432.
  Port 15432 is the local end of the SSH tunnel.

- -U havenbridge_admin
  Authenticate using the PostgreSQL role havenbridge_admin.

- -d havenbridge
  Connect directly to the havenbridge database.

Validation Result
-----------------
PASS

The HavenBridge PostgreSQL service running in havenbridge-postgres-0 can be
accessed securely from syrus through eph-cp01 using SSH tunneling and
kubectl port-forward.

The database list confirms that:
- havenbridge exists.
- havenbridge is owned by havenbridge_admin.
- postgres is also owned by havenbridge_admin.
- PostgreSQL system template databases template0 and template1 are present.
