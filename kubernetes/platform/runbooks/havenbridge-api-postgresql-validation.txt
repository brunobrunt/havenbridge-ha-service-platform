HavenBridge API Container and PostgreSQL Validation Runbook
=============================================================

Document purpose
----------------
This runbook records the steps used on July 30, 2026 to:

1. Validate the HavenBridge API Docker image.
2. Confirm that the image runs as a non-root user.
3. Connect the local Docker container on Syrus to PostgreSQL in Kubernetes.
4. troubleshoot database connectivity and authentication problems.
5. Confirm that the API created its PostgreSQL tables successfully.

6. Display the PostgreSQL password only when necessary
------------------------------------------------------
SECURITY WARNING:
This command prints the plaintext password. Do not paste the password into Git,
documentation, screenshots, tickets, or chat messages.

Run on eph-cp01:

  kubectl get secret \
    havenbridge-postgres-secret \
    --namespace havenbridge \
    --output jsonpath='{.data.POSTGRES_PASSWORD}' \
    | base64 --decode

  echo

Kubernetes Secret values are Base64-encoded. Base64 is encoding, not encryption.

8. Copy the PostgreSQL password securely to Syrus
-------------------------------------------------
The preferred method is to retrieve the Secret directly through SSH instead of
manually copying and pasting the password.

Run on Syrus:

  ssh -i /home/alabi/.ssh/eph_k8s \
    mino@172.16.10.31 \

    /home/alabi/projects/havenbridge-ha-service-platform/applications/havenbridge-api/.runtime-secrets/postgres-password

Set restrictive permissions:

  sudo chmod 0400 \
    /home/alabi/projects/havenbridge-ha-service-platform/applications/havenbridge-api/.runtime-secrets/postgres-password

Confirm that the file exists and is not empty without displaying it:

  sudo test -s \
    /home/alabi/projects/havenbridge-ha-service-platform/applications/havenbridge-api/.runtime-secrets/postgres-password \

10. Open the SSH and kubectl database tunnel
--------------------------------------------
The API container runs on Syrus, while PostgreSQL runs inside Kubernetes.
The temporary connection path is:

  HavenBridge API container
          |
          v
  host.docker.internal:15432
          |
          v
  Syrus Docker bridge address 172.17.0.1:15432
          |
          v
  SSH tunnel
          |
          v
  eph-cp01 loopback port 15433
          |
          v
  kubectl port-forward
          |
          v
  havenbridge-postgres-0:5432

Open a separate Syrus terminal and run:

  ssh -i /home/alabi/.ssh/eph_k8s \
    -g \
    -L 172.17.0.1:15432:127.0.0.1:15433 \
    mino@172.16.10.31 \
    "kubectl port-forward \
      --namespace havenbridge \
      pod/havenbridge-postgres-0 \
      15433:5432"

Leave this terminal running.

Why port 15433 is used on eph-cp01:
Port 15432 was already occupied by an earlier kubectl port-forward process.
Any unused remote loopback port can be used as long as the SSH forwarding
destination and kubectl port-forward listening port match.

Verify the Syrus listener in another terminal:

  sudo ss -ltnp | grep 15432

Expected listener:

  172.17.0.1:15432


11. Start the API container with PostgreSQL settings
----------------------------------------------------
Remove a failed or old test container:

  docker rm --force havenbridge-api-test 2>/dev/null || true

Run the API container:

  docker run \
    --detach \
    --name havenbridge-api-test \
    --publish 8000:8000 \
    --add-host host.docker.internal:host-gateway \
    --env POSTGRES_HOST=host.docker.internal \
    --env POSTGRES_PORT=15432 \
    --env POSTGRES_USER=havenbridge_admin \
    --env POSTGRES_DB=havenbridge \
    --env POSTGRES_PASSWORD_FILE=/run/secrets/postgres-password \
    --mount type=bind,source=/home/alabi/projects/havenbridge-ha-service-platform/applications/havenbridge-api/.runtime-secrets/postgres-password,target=/run/secrets/postgres-password,readonly \
    havenbridge-api:0.1.0

The password is mounted as a read-only file instead of being passed as a
plaintext environment variable.

16. Troubleshooting summary
---------------------------

Problem:
  kubectl: command not found on Syrus

Cause:
  kubectl is configured on eph-cp01, not Syrus.

Resolution:
  Run Kubernetes commands remotely with:

    ssh -i /home/alabi/.ssh/eph_k8s \
      mino@172.16.10.31 \
      "<kubectl command>"


Problem:
  No such file or directory for .runtime-secrets/postgres-password

Cause:
  The command was run on eph-cp01, or the directory did not exist on Syrus.

Resolution:
  Return to Syrus and run:

    mkdir -p \
      /home/alabi/projects/havenbridge-ha-service-platform/applications/havenbridge-api/.runtime-secrets


Problem:
  connection refused at 172.17.0.1:15432

Cause:
  The SSH tunnel was listening only on Syrus loopback address 127.0.0.1.
  Docker accessed the host through 172.17.0.1.

Resolution:
  Bind the local SSH listener to 172.17.0.1 and use -g:

    -g -L 172.17.0.1:15432:127.0.0.1:15433


Problem:
  unable to listen on port 15432 on eph-cp01

Cause:
  An existing kubectl port-forward process already used that port.

Resolution:
  Use another free eph-cp01 loopback port, such as 15433:

    15433:5432


Problem:
  password authentication failed for user havenbridge_admin

Cause:
  The manually created password file on Syrus did not match the Kubernetes
  Secret.

Resolution:
  Recreate the file directly from the Secret through SSH, then compare
  checksums if necessary.

Local checksum:

  sudo sha256sum \
    /home/alabi/projects/havenbridge-ha-service-platform/applications/havenbridge-api/.runtime-secrets/postgres-password

Remote checksum:

  ssh -i /home/alabi/.ssh/eph_k8s \
    mino@172.16.10.31 \
    "kubectl get secret havenbridge-postgres-secret \
      --namespace havenbridge \
      --output jsonpath='{.data.POSTGRES_PASSWORD}' \
      | base64 --decode \
      | sha256sum"

The two checksum values must match.
