HavenBridge API Egress NetworkPolicy — Positive Validation
===========================================================

Validation date:

Purpose
-------

This validation confirms that the HavenBridge API remained healthy after the
egress NetworkPolicy was applied.

The policy restricts outbound traffic from the HavenBridge API Pods and allows
only:

- Kubernetes DNS through CoreDNS on UDP/53 and TCP/53
- PostgreSQL on TCP/5432

-------------------------------

Command:

  mino@172.16.10.31 \
  'kubectl describe networkpolicy \
    allow-havenbridge-api-egress \
    --namespace havenbridge'

Observed output:

    To Port: 5432/TCP

      NamespaceSelector: kubernetes.io/metadata.name=havenbridge
      PodSelector: app.kubernetes.io/instance=havenbridge-postgres,app.kubernetes.io/name=postgresql
  Policy Types: Egress

Interpretation:

- The policy selects only Pods labelled:
  app.kubernetes.io/name=havenbridge-api

- The policy does not modify ingress traffic.

- The API Pods may send DNS requests to CoreDNS Pods in kube-system on:
  UDP/53
  TCP/53

- The API Pods may connect to the HavenBridge PostgreSQL Pod on:
  TCP/5432

- Other outbound destinations are denied by the egress isolation policy.

5. Validation Result
--------------------

The positive egress validation passed.

Confirmed:

- The egress NetworkPolicy is applied to the HavenBridge API Pods.
- DNS is allowed only to CoreDNS Pods on UDP/53 and TCP/53.
- PostgreSQL is allowed only on TCP/5432.
- Both API replicas remain Ready and Running.
- PostgreSQL remains Running.
- External readiness returns HTTP 200.
- The captured API logs show successful readiness and liveness requests.
- No relevant network or database errors were observed in the captured logs.

Important limitation:

This positive validation confirms that the application remained functional
after the policy was applied. A separate negative egress test is still required
to prove that an unapproved outbound destination is blocked.
