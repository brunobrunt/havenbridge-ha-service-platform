HavenBridge API Egress NetworkPolicy — Negative Validation Steps
================================================================

Purpose
-------

This validation proves that the HavenBridge API egress NetworkPolicy blocks an
outbound destination that is not explicitly allowed.

The production egress policy allows only:

- CoreDNS on UDP/53
- CoreDNS on TCP/53
- HavenBridge PostgreSQL on TCP/5432

The negative test attempts to connect to the CoreDNS metrics port TCP/9153.
Because TCP/9153 is not included in the egress policy, the connection should
time out.

Important EndpointSlice Observation
-----------------------------------

The test Job used:

app.kubernetes.io/name=havenbridge-api

That label caused the production API egress policy to select the test Pod.

The HavenBridge API Service also selects Pods using that label. Kubernetes
therefore created an additional EndpointSlice containing the test Pod:

havenbridge-api-7s9pw
Endpoint: 10.244.176.226
Port: <unset>

The test Pod was not Ready and did not expose the API named port, so it was not
a valid ready API backend. However, a validation Pod should not appear in the
production API Service EndpointSlices.

The temporary Job must be removed after the test.

Conclusion
----------

The negative API egress validation succeeded.

Confirmed:

- DNS resolution remained allowed through CoreDNS port 53.
- TCP/9153 was blocked.
- The connection timed out as expected.
- Evidence was saved.
- The temporary Job and Pod must be deleted.
- The API EndpointSlice must return to only the two real API Pod endpoints.
- External readiness must continue returning HTTP 200.


Recommended Improvement
-----------------------

Before repeating this test, revise the test design so the validation Pod uses a
unique label that the production API Service does not select. Apply an
equivalent temporary egress policy to that unique test label.
