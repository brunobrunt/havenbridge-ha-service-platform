HavenBridge v0.5.0 Application Version Reporting Validation
============================================================

Purpose
-------

Validate that the HavenBridge application version is supplied automatically
during the release Docker build and reported correctly by the running
application after deployment to Kubernetes.

Release
-------

Semantic version:

    v0.5.0

Release commit:

    5db454410b94f710909d805c12c257da74e87c75

Short commit:

    5db4544

Commit message:

    feat: automate HavenBridge application version reporting

The v0.5.0 release introduced automatic application-version reporting so that
the running HavenBridge API no longer depends on a hard-coded application
version.


Application Configuration
-------------------------

HavenBridge application configuration includes:

    app_version: str = "unreleased"

The value:

    unreleased

is used as the safe default when no release version is supplied.

During an official release, GitHub Actions overrides this value with the
semantic application version.


Docker Build-Time Version Injection
-----------------------------------

The HavenBridge API Dockerfile accepts the application version using:

    ARG APP_VERSION="unreleased"

and makes it available to the running container using:

    ENV APP_VERSION="${APP_VERSION}"

The Release workflow converts the Git release version into the application
version and supplies it to the Docker build.

For release:

    v0.5.0

the application version becomes:

    0.5.0

Release build concept:

    Git release version
        v0.5.0
            |
            v
    APP_VERSION
        0.5.0
            |
            v
    Docker build argument
            |
            v
    Docker environment
            |
            v
    Pydantic Settings
            |
            v
    settings.app_version


FastAPI Version Integration
---------------------------

The HavenBridge API reads the configured application version through:

    settings.app_version

The value is used by:

    FastAPI application metadata

and:

    GET /

This means the running application can identify its deployed software
version without maintaining a separate hard-coded version value in the
application source.

Significance
------------

Before v0.5.0, HavenBridge application-version reporting relied on a static
application value.

The v0.5.0 release proved that application version information could instead
be supplied automatically by the release process.

This established the version-reporting foundation later used by the automated
semantic-release implementation validated with v0.6.0.
