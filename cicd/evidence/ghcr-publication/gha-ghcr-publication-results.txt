Initial Publication Attempt
---------------------------

The initial Docker push failed.

Observed output included:

    The push refers to repository
    [ghcr.io/brunobrunt/havenbridge-api]

followed by image layers entering:

    Preparing

and:

    Waiting

The final registry error was:

    denied: permission_denied: write_package

GitHub Actions then reported:

    Process completed with exit code 1.

----------------------

Root Cause
----------

The workflow successfully authenticated to GitHub Container Registry using
GITHUB_TOKEN.

However, the HavenBridge repository did not initially have Write
authorization to the existing havenbridge-api package.

Therefore the workflow identity was known to GitHub, but it was not authorized
to publish a new version of that package.


Resolution
----------

The package access configuration was updated so:

    havenbridge-ha-service-platform

was granted:

    Write

access to:

    havenbridge-api


Rerun Result
------------

The same GitHub Actions workflow was rerun after fixing package authorization.

The rerun completed successfully.

Authentication vs Authorization Lesson
--------------------------------------

Authentication asks:

    Who are you?

Authorization asks:

    What are you allowed to do?

In this validation:

    Authentication
        =
    SUCCESS

    Authorization on first push
        =
    FAILED

After granting package Write access:

    Authorization
        =
    SUCCESS


Publication Boundary
--------------------

This validation published an image to GHCR.

It did NOT:

    deploy the new SHA image to Kubernetes
    update the HavenBridge Deployment
    perform a Kubernetes rollout
    change the running production application version

Those activities belong to the later Continuous Deployment stage.
